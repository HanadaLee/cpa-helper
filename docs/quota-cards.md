# 日配额 / 周配额与额度卡

## 扣费与周期

- 日配额于北京时间次日 00:00 重置；周配额于北京时间下周一 00:00 重置。
- 日配额和周配额约束同一份基础用量。基础用量同时计入两者，任一耗尽就不能继续使用配额。当前可用配额为两者剩余值的较小值，不是两者相加。
- 可用配额与生效中的额度卡统一按到期时间升序抵扣。配额的下一重置时间为次日 00:00，早于该时间到期的额度卡优先；永久额度卡最后。同一到期时间先配额，再按额度卡 ID。
- 额度卡抵扣不会占用日配额或周配额，配额耗尽时仍可用额度卡。当前可用余额 = 当前可用配额 + 有效额度卡剩余金额。
- 额度卡发放即生效，无需兑换。失效、过期或已用完的额度卡不参与抵扣。
- 保留“不限制余额”开关：开启后不计入配额，也不扣额度卡。
- 余额用尽后暂停 API 密钥；发放卡片、重置额度或进入新周期后自动恢复。手动禁用的密钥不会自动恢复。
- 后台每 15 秒检查到期、周期切换与密钥同步失败重试；扣费或管理操作后也会立即同步。实际请求限制仍依赖采集和上游密钥同步，并非请求前预授权。超出全部余额的请求差额会记录为“未覆盖”，不会伪造负余额。

## 管理与查询

- 用户管理：单人或批量发放、编辑、吊销额度卡/重置卡，重置单人、所选用户或全站用户的日配额/周配额。配额及额度卡余额以剩余进度条显示。
- 用户额度卡汇总进度条不计入已过期、已吊销的卡片；永久卡片若在北京时间当月 1 日 00:00 之前用完，也不再计入总额度。本月用完的永久卡片仍计入，尚有余额的永久卡片不受月份限制。用完时间按最后一笔扣款记录判断（无扣款流水的历史卡片使用其更新时间），不受后续名称编辑影响。历史卡片及扣款记录仍保留，实际余额与抵扣顺序不变。
- 我的配额：“配额管理”统一展示日配额、周配额、重置时间及配额重置记录；“额度管理”展示卡片及剩余进度。请求费用统一在“我的明细”和管理员“请求明细”列表查看，不再重复展示扣款流水。
- 额度卡状态：生效中、已用完、已过期、已失效（管理员吊销）。重置卡状态：未使用、已使用、已过期、已失效。
- 重置卡由用户手动使用，每张只能使用一次；清零日配额/周配额已用量，不改变下次周期重置时间，不改变额度卡余额。
- 历史扣款和重置记录保留。明细保留期清理不会删除额度卡扣款流水。

## 升级迁移

升级前备份数据库。迁移 `202609260001` 将每位用户的剩余每月额度转换为独立额度卡，有效期为迁移时刻起一个自然月（月末日期向当月最后一天收敛）；不限时余额转换为永久额度卡。余额为零的不发放。旧字段仅保留用于历史记录，不再作为可配置或可扣费额度。

新用户默认配额只保留日配额、周配额（默认均为 0）及原有不限制余额开关。原默认每月/不限时配置不再应用于新用户；已有用户余额由上述迁移保留。

额度卡后续可能已被扣费、编辑或吊销，不能安全逆向还原旧余额，因此此迁移禁止直接 Down；若需降级，应恢复升级前数据库备份。

迁移 `202609260002` 为扣款流水补充独立的“配额抵扣”金额，兼容旧版日/周分别扣款记录，避免将新版双计数误算为双倍收费。现有日/周已用量保持不变，新用量开始按共同配额规则累计，不追溯重扣或重置旧余额。
